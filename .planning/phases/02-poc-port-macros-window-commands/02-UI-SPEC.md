# Phase 2 — UI Design Contract

> Visual and interaction contract for the TerribleLuraHelper smile-arc helper window.
> This is a WoW Midnight (Interface 120005) Lua addon — not a web or mobile project.
> All "design system" references are Blizzard frame templates, atlas names, texture paths,
> font handles, and Lua ARGB tuples. Web equivalents (CSS tokens, breakpoints, npm packages)
> are not applicable and are replaced by their WoW-Lua analogs throughout.
>
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## 1. Visual Hierarchy and Layout

### 1.1 Frame Template Choice

**Use `BasicFrameTemplateWithInset`** (confirmed from wow-ui-source at
`Interface/AddOns/Blizzard_UIPanelTemplates/Mainline/UIPanelTemplates.xml` lines 638–699).

Rationale (per D-17):
- Provides a title bar with built-in `TitleText` FontString and `CloseButton` — no custom chrome needed for those elements.
- Provides a rock-texture background (`UI-Background-Rock`, horizTile/vertTile) that gives the frame a solid, opaque Blizzard-native look.
- Adds a marble inset area (`UI-Background-Marble`, horizTile/vertTile) inset 4px from top-24, 6px from sides, 4px from bottom — this is where the smile-arc content lives.
- Inherits all border textures (corners, top/bottom/left/right borders) from `BaseBasicFrameTemplate`.
- Does NOT include a portrait slot — correct, since no portrait is added in v1 (OOS per PROJECT.md).

**Do NOT use:**
- `BasicFrameTemplate` — same as above but no marble inset; content area would sit on raw rock texture with no visual separation from chrome.
- `ButtonFrameTemplate` — portrait region we don't need; adds visual weight for no benefit.
- `PortraitFrameTemplate` — same portrait issue as ButtonFrameTemplate.
- `BackdropTemplate` (POC approach) — dropped per D-17; custom purple backdrop replaced by Blizzard-native chrome.

### 1.2 Window Dimensions

**Width: 380px, Height: 320px** — verbatim from POC (`local W, H = 380, 320`), kept per D-18.

The `BasicFrameTemplateWithInset` chrome consumes:
- Top: ~24px (title bar area, from InsetBg anchor `y=-24`)
- Left: 4px, Right: 6px, Bottom: 4px (InsetBg insets from XML)

Effective inset content area: approximately **370 × 292px** (inner usable region for the smile-arc).

No dimension adjustment needed — the POC's bossView anchors at `TOP, win, TOP, 0, -38` which clears the title bar comfortably.

### 1.3 Title Bar Composition

The title bar occupies the top ~20–22px of the frame (above the inset). It contains, left to right:

```
[ BOSS/TANK LABEL AREA ... ]  [ Lock Btn ][ Close Btn ]
                                  ^20x20      ^24x24
```

**Title text:** `"Terrible L'ura Helper"` set via `frame.TitleText:SetText(...)` using the template's
built-in `TitleText` FontString (inherits `GameFontNormal` — FRIZQT 12pt with shadow, default color
is white/off-white from the GameFontNormal color vector). Per D-19: keep template's default color.
Do NOT force the POC's purple `(0.85, 0.4, 1.0)` on the title.

**Close button:** Template provides `frame.CloseButton` anchored at TOPRIGHT x=1 y=0 (24×24).
Uses Blizzard atlas `RedButton-Exit` / `RedButton-exit-pressed` / `RedButton-Highlight` (confirmed
from SharedUIPanelTemplates.xml lines 134–140). Script: `OnClick → win:Hide()`.

**Lock button:** Positioned immediately to the LEFT of CloseButton per D-14. See Section 3.1.

### 1.4 Smile-Arc Layout (Verbatim from POC — D-18)

All positions are relative to the `bossLabel` CENTER anchor (`SetPoint("CENTER", bossView, "CENTER", 0, 8)`).

**bossView sub-frame:**
- Size: `W - 40` × 220 px → **340 × 220 px**
- Anchor: `TOP, win, TOP, 0, -38`

**BOSS label:**
- Anchor: `CENTER, bossView, CENTER, 0, 8`
- Font: `Fonts\FRIZQT__.TTF`, size **18**, flags `"OUTLINE"`
- Text: `"BOSS"`
- Color: default (white — no explicit SetTextColor in POC for BOSS)

**TANK label:**
- Anchor: `CENTER, bossLabel, CENTER, 0, 60`
- Font: `Fonts\FRIZQT__.TTF`, size **14**, flags `"OUTLINE"`
- Text: `"TANK"`
- Color: default (white)

**Slot positions** (CENTER offset from bossLabel CENTER, in pixels):

| Slot | X offset | Y offset | Arrival order |
|------|----------|----------|---------------|
| 1 | +110 | +32 | First |
| 2 | +80 | -28 | Second |
| 3 | 0 | -60 | Third |
| 4 | -80 | -28 | Fourth |
| 5 | -110 | +32 | Fifth |

The arc forms a shallow smile curve (highest at slots 1 and 5, lowest at slot 3).

**Slot frame dimensions:**
- `SLOT_SIZE = 64` (outer frame, width and height)
- `ICON_SIZE = SLOT_SIZE - 8 = 56` (FontString font-size that renders the |T...|t marker)

**Slot index label (1–5 numeric):**
- Anchor: `TOP, slot, BOTTOM, 0, -2` (below each slot)
- Font handle: `GameFontNormalSmall`
- Text: `tostring(i)`
- Color: `(0.65, 0.65, 0.7, 0.85)` (dim gray — verbatim from POC)

## 2. Color and Typography

### 2.1 Color Palette

WoW Lua colors are expressed as `r, g, b[, a]` floats in range 0.0–1.0.
The 60/30/10 split is reframed for a game frame: dominant = background fill,
secondary = chrome/inset, accent = interactive state indicators.

| Role | ARGB Lua Tuple | Usage |
|------|---------------|-------|
| Dominant (60%) — background | `UI-Background-Rock` atlas (template) | Outer frame rock texture (tiles); no explicit color call needed |
| Secondary (30%) — inset | `UI-Background-Marble` atlas (template) | Inset content area marble texture; no explicit color call needed |
| Slot unfilled border | `r=0.3, g=0.2, b=0.5, a=0.7` | Slot frame border when no content |
| Slot unfilled background | `r=0.05, g=0.05, b=0.1, a=0.7` | Slot frame fill when empty |
| Slot filled border (accent) | `r=0.85, g=0.4, b=1.0, a=0.9` | Slot frame border after FillSlot; the one active color the user sees |
| Title bar | Template default | Blizzard-standard stone-and-gold title band |
| Title text | Template default (GameFontNormal white) | Do not override per D-19 |
| BOSS/TANK label | `SetTextColor` not called → inherits white | Default Blizzard white |
| Slot index label | `r=0.65, g=0.65, b=0.7, a=0.85` | Dim gray numeric labels |

**Accent reserved for:** filled slot border only (`slot:SetBackdropBorderColor(0.85, 0.4, 1.0, 0.9)` in `FillSlot`).
No other element uses this color in Phase 2.

**Note on backdrop removal:** The POC's purple window backdrop
(`SetBackdropColor(0.04, 0.0, 0.13, 0.9)`, `SetBackdropBorderColor(0.5, 0.0, 0.9, 1.0)`)
is DROPPED per D-17. The template supplies its own background. The slot frames still use
`BackdropTemplate` with `WHITE8x8` fill and border — that is NOT the outer window backdrop.

**Slot backdrop spec (unchanged from POC):**
```lua
slot:SetBackdrop({
    bgFile   = "Interface\\Buttons\\WHITE8x8",
    edgeFile = "Interface\\Buttons\\WHITE8x8",
    edgeSize = 1,
})
slot:SetBackdropColor(0.05, 0.05, 0.1, 0.7)
slot:SetBackdropBorderColor(0.3, 0.2, 0.5, 0.7)   -- unfilled state
-- On FillSlot:
slot:SetBackdropBorderColor(0.85, 0.4, 1.0, 0.9)   -- filled state
```

### 2.2 Typography

Blizzard fonts are named handles (global font objects), not point-sizes at call sites,
except when using explicit `SetFont`. Line height is not configurable in WoW FontStrings.

| Role | Font Handle / SetFont Call | Size | Flags | Usage |
|------|---------------------------|------|-------|-------|
| Title bar | `GameFontNormal` (template default) | 12pt (FRIZQT with shadow) | shadow | Window title "Terrible L'ura Helper" |
| BOSS label | `SetFont("Fonts\\FRIZQT__.TTF", 18, "OUTLINE")` | 18pt | OUTLINE | Center label |
| TANK label | `SetFont("Fonts\\FRIZQT__.TTF", 14, "OUTLINE")` | 14pt | OUTLINE | Tank-position label |
| Slot icon | `SetFont("Fonts\\FRIZQT__.TTF", 56, "OUTLINE")` | 56pt (ICON_SIZE) | OUTLINE | Renders `\|T...\|t` raid marker inline texture |
| Slot index | `GameFontNormalSmall` | ~10pt (template) | shadow | Numeric 1–5 below slot |

The 56pt slot FontString does not render visible glyph text — it acts as a sized container
for the `|T...|t` inline texture that Blizzard's text renderer embeds at the font's line height.
Using OUTLINE on it has no visual effect on the texture but matches the POC verbatim (D-18).

## 3. Interactive States

### 3.1 Lock Button

**Placement:** Immediately to the LEFT of `frame.CloseButton` in the title bar (D-14).

The template's CloseButton anchors at `TOPRIGHT x=1 y=0`. The CloseButton is 24×24.
The lock button must be anchored at:
```lua
lockBtn:SetPoint("TOPRIGHT", frame.CloseButton, "TOPLEFT", 2, 0)
```
This places the lock button 2px to the left of the close button's left edge, vertically aligned.

**Size:** 20×20 px. This is slightly smaller than the 24×24 close button, which is intentional —
the lock icon (padlock glyph) has a narrower visual footprint than the X glyph, and 20px makes
the pair look proportional rather than competing.

**Texture paths (D-16):**
- Locked state (drag disabled): `Interface\Buttons\LockButton-Locked-Up`
- Unlocked state (drag enabled): `Interface\Buttons\LockButton-Unlocked-Up`

These are classic WoW texture paths (present since WoW 2.0+). Verify on Midnight client by
checking that `lockBtn:GetNormalTexture()` returns non-nil after `SetNormalTexture(...)`.
If the paths resolve to blank on Midnight, fall back to the `lock` atlas string
(`lockBtn:SetNormalAtlas("groupfinder-icon-lock")` for locked,
`lockBtn:SetNormalAtlas("groupfinder-icon-unlock")` for unlocked — verify atlas names
via `/run print(C_Texture.GetAtlasInfo("groupfinder-icon-lock"))` in-game).

**Button states:**

| State | Normal Texture | Pushed Texture | Highlight |
|-------|---------------|----------------|-----------|
| Locked | `LockButton-Locked-Up` | `LockButton-Locked-Down` | `UI-Common-MouseHilight` (ADD blend) |
| Unlocked | `LockButton-Unlocked-Up` | `LockButton-Unlocked-Down` | `UI-Common-MouseHilight` (ADD blend) |

The highlight texture (`Interface\Buttons\UI-Common-MouseHilight`) is the standard Blizzard
hover glow used on `UIPanelSquareButton` and similar small frame buttons. Apply it via:
```lua
lockBtn:SetHighlightTexture("Interface\\Buttons\\UI-Common-MouseHilight", "ADD")
```

**Click behavior:**
1. Toggle `db.window.locked` (true ↔ false).
2. If now locked: `win:SetMovable(false); win:RegisterForDrag()` (no args = unregister).
3. If now unlocked: `win:SetMovable(true); win:RegisterForDrag("LeftButton")`.
4. Swap the NormalTexture to match new state.

**Default state:** Locked (`db.window.locked = true` per D-15). On first show, apply locked
texture and disable drag.

### 3.2 Drag Affordance

When **unlocked** (`db.window.locked = false`):
- `win:SetMovable(true)`
- `win:RegisterForDrag("LeftButton")`
- `win:SetScript("OnDragStart", win.StartMoving)`
- `win:SetScript("OnDragStop", function(self) self:StopMovingOrSizing(); <persist position> end)`
- No visual drag cursor change is needed — WoW's default move cursor appears automatically.

When **locked** (`db.window.locked = true`):
- `win:SetMovable(false)`
- `win:RegisterForDrag()` (no args)
- The OnDragStart script either removed or remains harmless (StartMoving is a no-op when not movable).

**Position persistence on drag stop (D-20):**
```lua
local point, relativeTo, relativePoint, x, y = win:GetPoint()
db.window.position = {
    point,
    relativeTo and relativeTo:GetName() or "UIParent",
    relativePoint,
    x,
    y,
}
```

### 3.3 Slot Fill Animation

None. The POC performs no animation — `FillSlot` calls `slot.fs:SetText(processed)` and
`slot:SetBackdropBorderColor(0.85, 0.4, 1.0, 0.9)` synchronously. Phase 2 matches this exactly.
No fade-in, no glow pulse. Slot fill is instantaneous.

### 3.4 Inactivity Self-Clear

After 20 seconds of no new `CHAT_MSG_*` event (per D-28, D-29):
- `ClearAll()` is called: `wipe(sequence)`, all slot FontStrings set to `""`, all slot borders
  reset to unfilled color `(0.3, 0.2, 0.5, 0.7)`.
- Named constant at top of `Window.lua`: `local INACTIVITY_TIMEOUT = 20`
- Timer via `C_Timer.NewTimer(INACTIVITY_TIMEOUT, callback)`.
- Each new message cancels the running timer and starts a fresh one.

### 3.5 Window Show / Hide

**Show:** `win:Show()` — reveals the frame. Applies saved position on first show per D-21:
```lua
if db.window.position then
    local pos = db.window.position
    win:ClearAllPoints()
    win:SetPoint(pos[1], _G[pos[2]] or UIParent, pos[3], pos[4], pos[5])
else
    win:ClearAllPoints()
    win:SetPoint("CENTER", UIParent, "CENTER", 200, 80)
end
```
Position is applied only once (on the first show after load). Subsequent show/hide cycles
do not reapply — frame remembers its last position from dragging.

**Hide:** `win:Hide()` — conceals frame. Does not wipe sequence (sequence persists in memory
while addon is enabled; only `/lura hide` wipes it per D-24/D-27).

**Scale:** Applied at frame creation and on refresh:
```lua
win:SetScale(db.window.scale)  -- range 0.50–2.00, default 1.00 per D-29
```
Phase 2 does not update scale live (no slider yet — that is Phase 3). Scale is applied once
on `ns:InitWindow()` and honored if the DB value was manually edited.

**Alpha (transparency):** Applied at frame creation and on refresh:
```lua
win:SetAlpha(db.window.alpha)  -- range 0.20–1.00, default 1.00 per D-35..37
```
Phase 2 does not update alpha live (no slider yet — that is Phase 3 / CFG-10). Alpha is
applied once on `ns:InitWindow()` and honored if the DB value was manually edited.
`SetAlpha` cascades to all child frames (slot frames, BOSS/TANK labels, slot index labels,
title text, lock button, close button) — the entire window fades together.

**Clamp to screen:** `win:SetClampedToScreen(true)` — applied at creation per D-22.

## 4. Accessibility

WoW Lua addons do not have keyboard focus navigation for custom frames (no tab-order API).
The following accessibility-adjacent constraints apply:

| Constraint | Implementation |
|-----------|----------------|
| Screen containment | `win:SetClampedToScreen(true)` — window cannot be dragged off screen |
| Readable labels | BOSS: 18pt OUTLINE, TANK: 14pt OUTLINE — both visible at default UI scale |
| Slot numerals | `GameFontNormalSmall` (~10pt) with `(0.65, 0.65, 0.7, 0.85)` — readable at 1.00 scale; low priority since slot position is the primary signal |
| Frame strata | Default for `BasicFrameTemplateWithInset` (MEDIUM) — sits above world but below DIALOG-strata panels |
| Lock button feedback | Texture swap on click gives clear state indication; no tooltip required for v1 |
| Mouse passthrough | Not applicable — `EnableMouse(true)` is the template default; the window is fully interactive |

No screen-reader, contrast-ratio, or keyboard-only requirements apply to this context.

## 5. Information Architecture

### 5.1 Slot Ordering and Spatial Semantics

Slots are **positional, not labeled by rune type**. The five slots encode arrival order (1→5),
not rune identity. The BOSS and TANK labels provide spatial orientation (where the boss faces,
where the tank stands relative to the semicircle of runes).

```
TANK
  |
[ 5 ]     [ 1 ]     ← arrival order right-to-left at top
  [ 4 ] [ 2 ]       ← second ring
      [3]            ← slot 3 = directly below boss
      BOSS
```

(Seen from the player's camera perspective looking at the boss from the TANK position.)

### 5.2 Empty State

When the sequence is empty (at load, after clear, after 20s timeout):
- All slot FontStrings contain `""` (no visible content).
- All slot borders are at unfilled color `(0.3, 0.2, 0.5, 0.7)`.
- BOSS and TANK labels remain visible at all times.
- No "empty state" copy or placeholder graphic is shown in the slots.
- The window itself may be hidden (if the user ran `/lura hide` or has `autoHide` set — but
  `autoHide` behavior is Phase 3 only; Phase 2 leaves the window visible while enabled).

### 5.3 Six-Press Wrap-Around

A 6th `CHAT_MSG_*` event while all 5 slots are filled triggers `ClearAll()` then immediately
fills slot 1 with the new message. From the user's perspective this is a clean reset —
all slots blank briefly, then slot 1 lights up with the new sequence's first marker.
No confirmation, no animation, no warning copy.

### 5.4 Slash Command Output (Visual Formatting)

`/lura help` (CMD-07) prints to the default chat frame using WoW color escape codes.
Format per D-CONTEXT specifics:

```
|cffaa44ffTerribleLuraHelper|r commands:
  |cffffd700/lura show|r       Enable + show window
  |cffffd700/lura hide|r       Disable + hide window
  |cffffd700/lura config|r     Open Options > AddOns > TLH (Phase 3)
  |cffffd700/lura help|r       Show this help
  |cffffd700/lura|r            Toggle enabled/disabled
|cffffd700/tlh|r is an alias for |cffffd700/lura|r with the same subcommands.
```

Color codes:
- Addon name: `|cffaa44ff` (purple-violet, matching the load banner color from Phase 1)
- Command text: `|cffffd700` (gold/yellow — standard WoW interactive text color)
- Reset: `|r`

The macro hint (MACR-05) after first successful registration uses the same purple prefix:
```
|cffaa44ffTLH|r macros: N created, N updated. Open /macro and drag them to your action bar.
```

The `/lura config` stub print (Phase 2 only) is plain text:
```
Config panel lands in Phase 3.
```

## 6. Component Reuse

All components in Phase 2 are either Blizzard-native templates/textures or raw CreateFrame calls.
No third-party registry, no shadcn, no npm.

| Component | Source | Reuse Type |
|-----------|--------|------------|

| Title FontString | `frame.TitleText` (template parentKey) | Direct access, SetText only |

frame (380×320px) with a smile-arc of 5 rune-display slots arranged per the POC geometry,
