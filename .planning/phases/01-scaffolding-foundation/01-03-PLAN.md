Final exact content:

    @echo off
    setlocal enabledelayedexpansion

    if "%~1"=="" (
        echo Usage: release.bat ^<version^>
        echo Example: release.bat 0.1.0
        exit /b 1
    )

    set "VERSION=%~1"
    set "TAG=v%VERSION%"
    set "SOURCE=%~dp0..\\"

    echo === Releasing TerribleLuraHelper %VERSION% ===

    rem D-08: push the CURRENT branch (not hardcoded main) so releases work from milestone/* branches.
    for /f "tokens=* USEBACKQ" %%b in (`git -C "%SOURCE%" rev-parse --abbrev-ref HEAD`) do set "BRANCH=%%b"
    if "!BRANCH!"=="" (
        echo ERROR: could not determine current branch.
        exit /b 1
    )

    git -C "%SOURCE%" tag -a "%TAG%" -m "Release %VERSION%"
    if errorlevel 1 (
        echo ERROR: Tag creation failed.
        exit /b 1
    )

    git -C "%SOURCE%" push origin !BRANCH! "%TAG%"
    if errorlevel 1 (
        echo ERROR: Push failed.
        exit /b 1
    )

    echo === Released %TAG% from branch !BRANCH! — GitHub Actions will handle packaging ===

The `for /f` block captures `git rev-parse --abbrev-ref HEAD` into `%BRANCH%`. The `setlocal enabledelayedexpansion` at the top + `!BRANCH!` syntax (not `%BRANCH%`) is required because `%BRANCH%` would expand at parse-time inside the `if "%~1"==""` block and be empty. The defensive empty-branch check guards against detached-HEAD weirdness.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner to repo content | The workflow checks out the repo (`actions/checkout@v4`) and reads CHANGELOG.md. CHANGELOG.md is contributor-controlled but is regulated by the repo's branch protection / PR review process; only maintainers can merge changes to main. |
| GitHub Actions to GitHub API | The workflow uses `secrets.GITHUB_TOKEN` (auto-provided) to upload release assets via `BigWigsMods/packager@v2`. CurseForge/Wago tokens are intentionally NOT wired up in Phase 1 (commented out per CONTEXT.md deferred). |
| Local user to WoW AddOns folder | install.bat writes into `%PROGRAMFILES(x86)%\World of Warcraft\...` — a privileged path. The user runs it explicitly; OS controls access. |
| release.bat to origin | release.bat creates and pushes a Git tag. The user must be authenticated to push to origin; standard developer credential flow. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Tampering | Malicious CHANGELOG.md content reaching `awk` in the GHA workflow | accept | `awk` reads CHANGELOG.md as text; it does not execute it. The awk pattern `/^## /{if(found) exit; found=1} found` only does line-classification and pass-through. There is no shell interpolation of CHANGELOG content. CHANGELOG.md is a markdown file edited via PR review. |
| T-01-10 | Elevation of Privilege | `BigWigsMods/packager@v2` action being compromised upstream | mitigate | Pinned to major version `@v2` (matches TBT's choice — same supply-chain risk profile, well-vetted action used by the BigWigs ecosystem). Future hardening: pin to a specific commit SHA after the first successful release run. Out of scope for Phase 1. |
| T-01-11 | Denial of Service | release.bat tagging and pushing from a wrong branch | mitigate | D-08 fix uses `git rev-parse --abbrev-ref HEAD` to capture the current branch, with a defensive empty-branch guard for detached HEAD. The user accepts (per D-08) that they may release from a dirty milestone branch — that's a workflow choice, not a security issue. |
| T-01-12 | Information Disclosure | Hardcoded paths in install.bat exposing local layout | accept | install.bat is a developer-local script, not shipped in the addon ZIP (ignored by .pkgmeta `scripts` entry). Path is well-known WoW retail install path. |
| T-01-13 | Repudiation | Released tag without a tracking commit | mitigate | release.bat creates an annotated tag (`git tag -a "%TAG%" -m "Release %VERSION%"`) — annotated tags carry author + message metadata. Push includes both tag and current branch in one atomic command, so the tagged commit is always reachable from a branch ref. |
</threat_model>
