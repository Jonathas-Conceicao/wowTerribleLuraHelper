## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings panel UI → addon Lua | User clicks a control; framework runs the SetValueChangedCallback. Insecure code path; addon code may call any non-protected API. |
| User chat → addon | `CHAT_MSG_*` events deliver `msg` (tainted). The Phase 2 chat handler in Window.lua already mitigates by passing `msg` opaquely through `C_ChatInfo.ReplaceIconAndGroupExpressions`. Phase 3 does NOT touch this path. |
| User combat boundary | `PLAYER_REGEN_DISABLED` enters combat — `CreateMacro` / `EditMacro` become protected. `PLAYER_REGEN_ENABLED` exits — they unblock. |
| Addon → SavedVariables disk | `Settings.RegisterAddOnSetting` framework writes `db.*` keys on every change. Addon does NOT write the DB from change callbacks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `Settings.OpenToCategory(name)` footgun | mitigate | Always pass `ns.settingsCategoryID` (a number from `category:GetID()`); never pass the category name string. | T-03-02 | Tampering | Direct DB writes from change callbacks would leak addon state | mitigate | Use `Settings.RegisterAddOnSetting` (NOT proxy); the framework auto-writes through. Change callbacks call `ns:SetWindowScale(value)` / `ns:OnAutoHideChanged(value)` etc — pure runtime apply, NEVER `db.window.scale = value`. Verified by inspection: zero `db.* = value` writes inside Config.lua callback bodies. |
| T-03-03 | Tampering | Hard taint regression — accidental `msg` indexing in new code paths | mitigate | All five Phase 3 tasks add `grep -nE 'SendChatMessage\|msg:(gsub\|match\|find\|len\|sub\|rep)\|#msg\|msg \.\.\|\.\. msg'` to their verify gate. Phase 3 introduces no new `CHAT_MSG_*` handlers; the only path that touches `msg` (Window.lua line 281) is unchanged. |
| T-03-04 | Repudiation | User-action confirmation drift (e.g., Recreate Macros silently no-op) | mitigate | OnClick handlers print explicit confirm/error notices verbatim from UI-SPEC §Copywriting Contract. Combat-blocked path prints the deferral notice; success path prints `Macros recreated.` regardless of `macrosPrintedThisSession`. |
| T-03-05 | Information Disclosure | None — no PII handled | accept | Addon stores window position, scale, alpha, channel flags, macro channel — all addon-local UI state. No identity, location, gold, or character-secret data. |
| T-03-06 | Denial of Service | Combat-deferral retry frame leak in `ns:OnMacroChannelChanged` | mitigate | The retry frame self-unregisters on `PLAYER_REGEN_ENABLED` once `registrationDeferred=false`. Each rapid-fire dropdown change in combat creates one frame; each combat-end fires `PLAYER_REGEN_ENABLED` → all queued frames check `registrationDeferred` and self-clean after the first one's `RegisterMacros` succeeds.
