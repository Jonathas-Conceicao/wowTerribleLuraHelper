## v1.0.0 Requirements (Polish & Defaults) — ✅ All shipped

### Helper Window — click-through and combat-state coupling

- [x] **WIN-11**: When the helper window is locked, mouse clicks pass through it — clicks on the smile-arc area, slot frames, lock button, and close button are all ignored, and any UI element beneath the window receives the click. Drag-to-move is also disabled (existing WIN-05 behavior preserved). Implementation must call `EnableMouse(false)` on the window AND iterate over all `slotFrames` calling the same (cascade is NOT automatic — see PITFALLS.md CT-1).
- [x] **WIN-12**: When the helper window is unlocked, full mouse interaction is restored — clicks, hover, and click-and-drag-to-move all work exactly as in v0.1.0. Drag is re-registered via `RegisterForDrag()`; `EnableMouse(true)` is called on window + all slot frames.
- [x] **WIN-13**: While "auto-hide when empty in combat" is on AND the player is OUT of combat, the helper window stays visible (`alpha = db.window.alpha`) regardless of whether the slot sequence is empty. This is the core reframe — out-of-combat the window is visible-when-empty so the toggle being on is self-evident to the user.
- [x] **WIN-14**: While "auto-hide when empty in combat" is on AND the player is IN combat AND the slot sequence is empty, the helper window is soft-hidden (`SetAlpha(0)`; chat events stay registered per AMEND-01 — soft-hide MUST NOT use `win:Hide()`).
- [x] **WIN-15**: Combat-state transitions (`PLAYER_REGEN_ENABLED` / `PLAYER_REGEN_DISABLED`) re-evaluate the soft-hide state immediately, on every transition. Initial-login `PLAYER_REGEN_ENABLED` fires correctly seed combat state via `InCombatLockdown()` at frame creation.

### Config Panel — reference image, dynamic label, relabeled toggle

- [x] **CFG-12**: A wide static reference image (the rune → raid-marker cheat sheet — `reference.tga` at the addon root) appears as the first visual element in the config panel under Options > AddOns > TerribleLuraHelper, above all section headers and controls. Image is registered via `Settings.CreateElementInitializer("TLHSymbolReferenceTemplate", { texturePath = "Interface\\AddOns\\TerribleLuraHelper\\reference.tga" })` added FIRST in the vertical-layout registration sequence (insertion order = display order). Texture frame dimensions match panel width with the texture's 319×143 aspect preserved.
- [x] **CFG-13**: The Show/Hide window button label updates live whenever the window's visibility changes via any code path (slash command `/lura show|hide|toggle`, on-window close button, auto-hide-when-empty cycle, `/tlh` alias, panel button click). Implementation: `SettingsInbound.RepairDisplay()` guarded by `SettingsPanel:IsShown()`, called from `ns:NotifyWindowVisibilityChanged()` invoked from every visibility-changing path in `Window.lua`. **Soft-hidden window (`alpha=0` while frame is `:IsShown()`) counts as VISIBLE** — button reads "Hide window" in that state (engineering-truth model; user-confirmed UX choice).
- [x] **CFG-14**: The auto-hide setting label changes from "Auto-hide when empty" → "Auto-hide when empty in combat". Tooltip text updates to explain the new semantics: "When on, the helper window stays visible while you're out of combat (so you remember the toggle is on); in combat, it hides while the rune sequence is empty and reappears when a marker arrives." Existing users' `db.window.autoHide` value is preserved on upgrade (semantics shift toward LESS hiding — strictly safer for existing users).

### New Defaults & Backfill Safety

- [x] **SCAF-13**: First-run default for `listenChannels` changes — only `SAY = true`; `RAID`, `RAID_LEADER`, `RAID_WARNING`, `INSTANCE_CHAT`, `INSTANCE_CHAT_LEADER` all default to `false` (was: all six = `true` per SCAF-03). Reflects most-common pug/casual usage where SAY is the universally-visible channel inside instances.
- [x] **SCAF-14**: First-run default for `macroChannel` changes from `"RAID"` to `"SAY"` (was: `"RAID"`). Macros are recreated to send to `/s` instead of `/raid` on first install.
- [x] **SCAF-15**: Default-changes from SCAF-13 and SCAF-14 MUST NOT clobber existing users' choices on upgrade. Backfill code uses `if db.X == nil then db.X = DEFAULT` idiom (never `db.X = db.X or DEFAULT` — clobbers explicit `false`). Verified by smoke test: install v1.0.0 over a v0.1.0 SavedVariables file with custom channel choices, confirm choices preserved.

### Asset Pipeline

- [x] **SCAF-16**: Cheat-sheet image asset is delivered as `reference.tga` at the addon root (RGBA, 319×143, 8-bit alpha). Repo-only source `assets/reference.png` is excluded from release zips by the existing `.pkgmeta` ignore rule (`*.png`); TGA ships automatically. Texture loaded via `SetTexture("Interface\\AddOns\\TerribleLuraHelper\\reference.tga")`.
- [x] **SCAF-17**: Texture renders correctly in-game (no solid-green silent-failure mode from non-POT dimensions). Verified during in-game smoke test before tagging v1.0.0. If non-POT causes rendering failure, repad the TGA to power-of-two (e.g. 512×256 or 1024×512) and use `SetTexCoord(0, 319/512, 0, 143/256)` for letterboxing.

### Cross-cutting Safety / Invariants

- [x] **SAFE-05**: `applySoftHideState()` continues to use `SetAlpha(0)` exclusively, NEVER `win:Hide()` — preserves AMEND-01 (window-visibility-gated chat-event registration: `OnHide` would unregister chat events and break the next macro press in combat). Verified by code review at PR time + in-game smoke test (autoHide=on, in-combat, empty sequence; press a TLH macro; confirm slot fills).
- [x] **SAFE-06**: No usage of `db.X = db.X or DEFAULT` pattern anywhere in the addon (clobbers explicit `false` values). All backfill paths use `if db.X == nil then`. Verified by grep at PR time: `git grep "= db\." | grep " or "` must return zero matches.
