## v1.1.0 Requirements (QoL Update) — ✅ All shipped

### Verbose-Marker Toggle

- [x] **MACR-06**: When `db.verboseMarkers == true`, the four marker macros emit verbose tokens — `TLH_Diamond` → `{diamond}`, `TLH_Triangle` → `{triangle}`, `TLH_Circle` → `{circle}`, `TLH_Cross` → `{cross}`. `TLH_T` is unchanged (still sends the literal letter "T" — that's the 5th rune in the L'ura encounter; the star icon on the macro is for action-bar recognizability only). **Shipped Phase 7 via dual-field MACROS table + payload-selection conditional in RegisterMacros.**
- [x] **MACR-07**: When `db.verboseMarkers == false`, the four marker macros emit their original `{rt#}` payloads — `TLH_Diamond` → `{rt3}`, `TLH_Triangle` → `{rt4}`, `TLH_Circle` → `{rt2}`, `TLH_Cross` → `{rt7}`. `TLH_T` unchanged. **Shipped Phase 7 — promoted from "rollback path" to "default" during UAT (AMEND-07-01-UAT-01) after localization implication outweighed the cross-chat-addon benefit.**
- [x] **CFG-15**: New "Use verbose markers" checkbox in the config panel under Options > AddOns > TerribleLuraHelper. **Shipped Phase 7 as (3aa) in `RegisterMacroSection` between channel dropdown (3a) and Recreate button (3b).**
- [x] **CFG-16**: Toggle change triggers `ns:RegisterMacros()` to rebuild the four marker macros in place. Combat-lockdown deferral via existing `regenFrame`. Prints `TLH: Verbose markers on/off. Macros updated.` (with deferred-in-combat variant). **Shipped Phase 7 via `ns:OnVerboseMarkersChanged(value)` mirroring `OnMacroChannelChanged`.**
- [x] **SCAF-18**: First-run default `db.verboseMarkers = false`. Backfill uses SAFE-06 idiom `if db.verboseMarkers == nil then db.verboseMarkers = false`. **Shipped Phase 7 — default flipped from `true` to `false` during UAT (2026-05-16, AMEND-07-01-UAT-01) after the English-client-only localization implication was confirmed as the dominant factor for raid groups with mixed-locale players.**

### Zone-Aware Auto Show/Hide (March of Quel'danas)

- [x] **WIN-16**: The addon registers `PLAYER_ENTERING_WORLD` and `ZONE_CHANGED_NEW_AREA`. On each fire, it queries the player's current instance via `GetInstanceInfo()` and compares against the hardcoded `LURA_RAID_INSTANCE_ID = 2913` constant. In raid → call the existing window-show path. Out of raid → call the existing window-hide path. **Shipped Phase 8.** (Research-driven pivot from CONTEXT D-08's original `C_Map.GetBestMapForUnit` proposal to `GetInstanceInfo()` instanceID — difficulty-agnostic across all 5 Midnight raid difficulties.)
- [x] **WIN-17**: Manual `/lura show` and `/lura hide` continue to work and are re-evaluated on the next zone event. `/reload` while inside the raid re-shows the window. **Shipped Phase 8 via re-evaluate-on-every-fire handler design (no state tracking, leveraging OnShow/OnHide transition-only semantics per RESEARCH §Q4).**
- [x] **SCAF-19**: The March of Quel'danas raid instanceID is encoded as a hardcoded numeric constant in `Core.lua`. Localization-safe — no `GetZoneText` / `GetRealZoneText` / `GetMinimapZoneText` in the auto-handler. **Shipped Phase 8 via `LURA_RAID_INSTANCE_ID = 2913` (captured live during UAT via `DEBUG_ZONE_INFO` flag; two-track placeholder approach worked cleanly — sentinel `0` → captured ID → patched).**
- [x] **SAFE-07**: Zone-change auto show/hide routes through the same `Show()` / `Hide()` paths used by `/lura show` and `/lura hide`. Does NOT use `SetAlpha(0)` soft-hide for the zone-leave case — full `Hide()` is required to correctly unregister chat events (AMEND-01 invariant). **Shipped Phase 8 — defense-in-depth verified across 8 places in the plan; UAT checkpoint 3 confirmed `OnHide` unregisters chat events on raid exit.**
