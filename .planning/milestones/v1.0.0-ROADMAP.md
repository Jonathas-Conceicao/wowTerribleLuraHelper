## Overview

TerribleLuraHelper ports a working WeakerScripts POC (`LuraPatternHelper.lua`, 297 lines) into a standalone WoW Midnight addon and adds a config panel under Options > AddOns. The journey is short and goal-shaped: stand up the project skeleton (mirroring TerribleBuffTracker's release pipeline) so the addon loads, then lift the POC's chat-pipe + smile-arc UI + macros into the addon while adding the new `/lura hide` = "disable processing" semantics, and finally wrap it all in a Settings-API-driven config panel that wires the channel filters, scale slider, auto-hide toggle, and action buttons through to the runtime. All milestone work lives on a `milestone/0.1.0` branch and is squash-merged to `main`.

**v1.0.0 (Polish & Defaults):** Tightens the core UX on top of the shipped v0.1.0 foundation. Key additions: click-through when locked, SAY-centric first-run defaults (with safe backfill), auto-hide-when-empty reframed as in-combat-only, dynamic Show/Hide button label in the config panel, and a built-in symbol reference image for new users. All milestone work lives on `milestone/<version>` and is squash-merged to `main`.

On first login (out of combat), opening `/macro` shows five player macros named `TLH_Diamond`, `TLH_Triangle`, `TLH_Circle`, `TLH_Cross`, `TLH_T` with raid-marker icons; logging in mid-combat creates them on the next `PLAYER_REGEN_ENABLED`; subsequent logins update them in place (no duplicates).
  2. ### Phase 4: SAY Defaults + Click-Through
**Goal**: Fresh installs get SAY-only defaults that match real pug/casual usage, existing users keep their choices untouched, and a locked helper window is fully pass-through so it never intercepts raid clicks.
**Depends on**: Phase 3
**Requirements**: SCAF-13, SCAF-14, SCAF-15, SAFE-06, WIN-11, WIN-12
**Success Criteria** (what must be TRUE):
  1. On a brand-new SavedVariables file (fresh install), `listenChannels` has only `SAY = true` and all other channels default to `false`; `macroChannel` is `"SAY"`; the five TLH_* macros send to `/s` on first creation.
  2. Installing v1.0.0 over a v0.1.0 SavedVariables file with custom channel choices (e.g., RAID=true, SAY=false) preserves every existing choice exactly — no channel flag is reset, no macroChannel is overwritten.
  3. A grep of the codebase finds zero instances of the `db.X = db.X or DEFAULT` anti-pattern; every backfill path uses `if db.X == nil then db.X = DEFAULT end`.
  4. When the helper window is locked, clicking anywhere on the window frame, slot areas, or close button passes the click through to whatever UI element is beneath — the window is fully inert to mouse interaction.
  5. When the helper window is unlocked, full mouse interaction is restored — the window responds to clicks and can be dragged anywhere on its frame (the window has no separate title bar) exactly as in v0.1.0; subsequent lock/unlock cycles are idempotent.

### Phase 5: Auto-Hide Combat Reframe
**Goal**: The auto-hide toggle becomes in-combat-only — out of combat the empty window stays visible so users can see the toggle is active, while in-combat hide-when-empty behavior is preserved; combat-state transitions trigger immediate re-evaluation.
**Depends on**: Phase 4
**Requirements**: WIN-13, WIN-14, WIN-15, CFG-14, SAFE-05
**Success Criteria** (what must be TRUE):
  1. With "auto-hide when empty in combat" on and the player out of combat, the helper window remains visible even when the slot sequence is empty — the window does not soft-hide between pulls or at the login screen.
  2. With "auto-hide when empty in combat" on and the player in combat, the helper window soft-hides (`alpha=0`) when the slot sequence is empty; pressing a TLH_* macro causes the window to reappear and the slot to fill — confirming chat events stayed registered during soft-hide (AMEND-01 invariant preserved).
  3. Entering combat (PLAYER_REGEN_DISABLED) while auto-hide is on and the sequence is empty immediately soft-hides the window; leaving combat (PLAYER_REGEN_ENABLED) with an empty sequence immediately restores the window to full alpha.
  4. The config-panel checkbox reads "Auto-hide when empty in combat" and its tooltip explains that out-of-combat the window stays visible as a reminder, while in-combat it hides when empty.
  5. `applySoftHideState` uses `SetAlpha(0)` exclusively — no `win:Hide()` call — verified by code review: the window's `OnHide` handler never fires as a result of auto-hide logic, and chat events remain registered throughout every combat-state transition.

### Phase 6: Dynamic Label + Symbol Reference Image
**Goal**: The config-panel Show/Hide button label always reflects the current window state regardless of how the state changed, and new users see a built-in rune-to-marker cheat sheet at the top of the config panel before any other controls.
**Depends on**: Phase 5
**Requirements**: CFG-13, CFG-12, SCAF-16, SCAF-17
**Success Criteria** (what must be TRUE):
  1. While the config panel is open, running `/lura show` or `/lura hide` (or clicking the panel's own Show/Hide button) causes the button label to flip between "Show window" and "Hide window" immediately — no panel close/reopen required.
  2. A window soft-hidden by the auto-hide-in-combat logic (Phase 5) while the config panel is open does NOT flip the button label to "Show window" — the label reads "Hide window" because `win:IsShown()` is still true; this is the correct engineering-truth model confirmed during v1.0.0 questioning.
  3. The config panel under Options > AddOns > TerribleLuraHelper displays a wide static image as the first visual element above all section headers; the image is the Diamond/Triangle/Circle/Cross/T rune-to-marker cheat sheet, and it renders correctly (not solid green) in-game.
  4. The rendered cheat-sheet image preserves the 319x143 aspect ratio (or the equivalent power-of-two padded variant with correct `SetTexCoord`) — symbols are legible and not stretched or clipped.
  5. Unzipping a test release artifact confirms `reference.tga` (or the equivalent TGA file) is present in the zip alongside the Lua files — the asset ships via the normal BigWigs Packager pipeline, not just via `install.bat`.
