<objective>
Phase 5: Auto-Hide Combat Reframe. Two outcomes:

1. **Combat-state-coupled soft-hide** (WIN-13, WIN-14, WIN-15) — extend `applySoftHideState`'s condition with an `and inCombat` clause so the auto-hide-when-empty behavior only fires while the player is in combat. Out of combat with empty sequence, the window stays visible (so users see the toggle is on). Combat-state transitions (`PLAYER_REGEN_DISABLED` / `PLAYER_REGEN_ENABLED`) re-evaluate immediately via a new permanent `combatFrame` listener; initial-login seed via `InCombatLockdown()` handles `/reload`-mid-combat.

2. **Config-panel relabel** (CFG-14) — auto-hide checkbox label flips from "Auto-hide when empty" to "Auto-hide when empty in combat"; tooltip text rewritten to describe the new semantics.

Plus the **SAFE-05 invariant guardrail** — a 5-line block-comment immediately above `applySoftHideState` reminding future contributors that soft-hide MUST use `SetAlpha(0)`, NEVER `win:Hide()` (the AMEND-01 origin from Phase 2's verification).

Purpose: Make the auto-hide toggle's effect self-evident out of combat (window-stays-visible-when-empty signals "this is on") while preserving the in-combat clean-display behavior. Existing user `db.window.autoHide` values carry forward — the semantic shift is toward LESS hiding, strictly safer.

Output: Modified Window.lua (+1 Lua-local, +1 InCombatLockdown seed, +~10 lines combatFrame block, +5 lines SAFE-05 comment, +1 token in applySoftHideState condition) and Config.lua (2 string changes — label + tooltip). Zero new exports, zero new dependencies, zero schema migration.
