The template is a minimal virtual Frame with a single child Texture in layer "ARTWORK". The texture path comes from `self.data.texturePath` populated by `Settings.CreateElementInitializer("TLHSymbolReferenceTemplate", data)` in Task 3.

Exact file content (line-for-line):

```xml
<Ui xmlns="http://www.blizzard.com/wow/ui/" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://www.blizzard.com/wow/ui/ ..\FrameXML\UI.xsd">
    <Frame name="TLHSymbolReferenceTemplate" virtual="true">
        <Size x="319" y="143"/>
        <Layers>
            <Layer level="ARTWORK">
                <Texture parentKey="Image" setAllPoints="true"/>
            </Layer>
        </Layers>
        <Scripts>
            <OnLoad>
                if self.data and self.data.texturePath then
                    self.Image:SetTexture(self.data.texturePath)
                end
            </OnLoad>
        </Scripts>
    </Frame>
</Ui>
```

Notes for the executor:
- `parentKey="Image"` exposes the texture as `self.Image` to the OnLoad script. This matches Blizzard's pattern in `Blizzard_SettingControls.xml` (Title FontString uses `parentKey="Title"` and is read as `self.Title`).
- `setAllPoints="true"` anchors the texture to fill the frame (319x143 → 319x143 — no aspect distortion possible per D-06).
- The `if self.data and self.data.texturePath then` guard handles the edge case where the template is instantiated without a data table (defensive — should never fire in our use, but cheap insurance and matches Blizzard's Mixin guards).
- Per D-02 + STACK.md: this is a **path-string** SetTexture (not a FileDataID). Backslash escaping inside an XML script block: the path `Interface\AddOns\TerribleLuraHelper\reference.tga` arrives as a Lua string literal in Task 3 with `\\` doubled escapes; the texturePath value in self.data is a normal Lua string by the time OnLoad reads it.

```lua
-- Phase 6 / CFG-13. The Show/Hide button label uses CreateSettingsButtonInitializer's
-- buttonText closure (Config.lua:201-207) which the framework only re-evaluates when
-- the panel runs Init for the element. This hook lets visibility-changing call sites
-- (ShowWindow, HideWindow, RestoreWindowVisibility) tell the framework to re-init
-- visible elements via SettingsInbound.RepairDisplay, so the label flips live without
-- the user having to close-and-reopen the panel. The early-exit guard makes this a

-- D-12: applySoftHideState does NOT call this hook (soft-hide changes alpha only,
-- IsShown stays true, label is correct without a refresh — engineering-truth model).
function ns:NotifyWindowVisibilityChanged()
	if SettingsPanel and SettingsPanel:IsShown() then
		SettingsInbound.RepairDisplay()
	end
end
```

- `SettingsPanel` is the Blizzard global (the actual panel frame); checking it for nil is defensive against early-load timing where SettingsPanel hasn't been instantiated yet.
- `SettingsInbound.RepairDisplay()` is the verified API per STACK.md (location: `Blizzard_SettingsInbound.lua:156`); calling it while the panel is shown re-runs Init for visible elements, which re-evaluates the buttonText closure.
